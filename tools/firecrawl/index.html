Failed requests are not charged, but a page returning 403 or 404 still costs 1 credit. Pay-as-you-go top-ups in $5 increments exist on paid plans.

Firecrawl sits at the layer AI agents actually need: give it a URL and it returns clean markdown, structured JSON, screenshots or a full site crawl, with the proxy rotation, JavaScript rendering and bot-blocking handled behind the API. Because agents and RAG pipelines need parsed web data rather than raw HTML, Firecrawl became the default scraping layer for a large part of the Claude and LangChain crowd - including teams that previously maintained their own Scrapy stacks.

Where the money angle sits

Three income streams run through Firecrawl. First, productized data services: freelancers sell competitor price monitoring, real-estate listings, lead lists and news aggregation as monthly retainers - work that took a week of manual scraping now runs as a scheduled crawl for a few dollars of credits. Second, RAG and chatbot builds: agencies wiring client documents and websites into retrieval pipelines charge for the integration, and the MCP server means Claude Code can crawl a target site mid-task without custom retrieval code. Third, internal tooling for your own products - price trackers, directory sites, market-research reports - where scraping cost is the only variable cost.

The legal layer is yours to manage, not Firecrawl's. Scraping legality depends on the target site's terms, robots.txt and the data you collect; the API handles the technical layer only. Check robots.txt, avoid personal data unless you understand your jurisdiction's rules, and prefer official APIs where they exist - our web scraping tools comparison covers this in more detail.

The honest drawbacks

Structured extraction is where budgets inflate: a 10,000-page crawl with JSON output costs 50,000 credits, half a Standard plan. Bot-protected sites sometimes burn credits returning error pages, and there is no refund for a 403 that yielded nothing. The EUR-default display on the pricing page makes quick comparisons awkward. And against Apify, Firecrawl trades the thousands-of-actors ecosystem for a cleaner general-purpose API - if a ready-made actor exists for your target site, Apify wins; if you need LLM-clean output piped into agents, Firecrawl usually does. Browse AI covers the no-code monitoring crowd, and Tavily competes on the search side rather than deep crawls.

Bottom line

For developers and agencies building agent or RAG systems, Firecrawl is the scraping layer to default to - the free tier proves the output quality before you pay anything. For no-code users or niche sites with ready-made actors, check the alternatives first. Current plans sit on the Firecrawl pricing page.

Questions we get asked

Firecrawl vs Apify - which should I use?

Different layers. Apify is a marketplace of thousands of ready-made actors for specific sites and platforms - if one exists for your target, it is the faster route. Firecrawl is a general-purpose API that returns LLM-clean markdown and JSON with an MCP server, which makes it the default scraping layer for agents and RAG builds. Our web scraping tools comparison breaks down more options.

Is web scraping with Firecrawl legal?

It depends on the target site, not on Firecrawl. Legality turns on the site's terms of service, robots.txt, and what data you collect - the API handles only the technical layer. Check robots.txt, avoid personal data unless you understand the rules in your jurisdiction, prefer official APIs where they exist, and keep commercial redistribution of scraped content in view. This is not legal advice; treat it as the checklist before your first crawl.

How do I use Firecrawl with Claude or other AI agents?

Add the Firecrawl MCP server to your MCP client config - Claude Code, Cursor and most agent frameworks support it. Once connected, the agent can scrape, crawl or search the web mid-task and read the cleaned markdown directly, without custom retrieval code. The free 1,000 monthly credits are enough to wire it up and test real workflows before deciding on a paid plan.
